# 데이터 수집 및 전처리 과정

## 1. 데이터 수집

본 프로젝트에서는 과일의 수확 적기를 판단하기 위해 과일 이미지를 수집한다.

수집 데이터는 다음과 같은 환경을 포함하도록 구성한다.

- 미숙 과일
- 수확 적기 과일
- 과숙 과일
- 잎이나 가지에 가려진 과일
- 여러 과일이 겹쳐 있는 경우
- 다양한 촬영 거리와 각도
- 직사광선 및 그림자 환경
- 다양한 밝기 환경
- 복잡한 배경 환경

## 2. 전처리 목적

본 시스템은 야외 환경에서 카메라를 이용하기 때문에 촬영 시간, 날씨, 조명, 그림자 등에 따라 이미지의 밝기와 색상이 달라질 수 있다.

또한 과일 주변에 잎, 가지, 토양 등의 배경이 존재하기 때문에 전체 이미지의 색상 정보를 그대로 사용하는 경우 수확 적기 판단에 영향을 줄 수 있다.

따라서 과일 객체를 먼저 탐지하고 해당 영역을 Crop한 후 색상 및 크기 특징을 분석하는 전처리 과정을 구성한다.

## 3. 전처리 Pipeline

Camera Image
↓
Image Quality Check
↓
Resize / Letterbox
↓
YOLO Fruit Detection
↓
Fruit Crop
↓
Color Preprocessing
↓
HSV / Lab Color Analysis
↓
Size / Shape Feature Extraction
↓
Harvest Readiness Decision

## 4. 이미지 품질 확인

촬영된 이미지에서 다음과 같은 품질 문제를 확인한다.

- Blur
- 과다 노출
- 저노출
- 노이즈
- 초점 불량

품질이 지나치게 낮은 이미지는 학습 및 분석에 적합하지 않은 데이터로 분류한다.

## 5. Resize / Letterbox

YOLO 모델의 입력 크기에 맞추기 위해 이미지를 Resize한다.

이미지의 가로세로 비율을 유지하면서 Letterbox 방식을 적용하여 과일의 형태가 과도하게 변형되는 것을 방지한다.

## 6. YOLO 과일 탐지

전처리된 이미지를 YOLO 모델에 입력하여 영상 속 과일의 위치를 탐지한다.

각 과일에 대해 Bounding Box를 생성하고 탐지된 영역을 이후 분석에 사용한다.

## 7. Fruit Crop

YOLO가 탐지한 Bounding Box를 기준으로 과일 영역을 Crop한다.

이를 통해 잎, 가지, 토양 등의 배경 영향을 줄이고 과일 자체의 특징을 분석할 수 있도록 한다.

## 8. 색상 전처리 및 분석

수확 적기 판단에서 색상 정보가 중요한 특징이므로 HSV 또는 Lab 색공간을 활용한다.

- Hue
- Saturation
- Value
- Lightness

등의 특징을 분석하여 과일의 색상 변화를 확인한다.

Gamma Correction이나 CLAHE 등의 조명 보정 기법은 실제 수집 데이터의 조명 환경을 확인한 후 필요한 경우 적용한다.

## 9. 크기 및 형태 특징 분석

Bounding Box의 크기와 비율 등을 이용하여 과일의 상대적인 크기와 형태를 분석한다.

카메라와 과일 사이의 거리에 따라 픽셀 크기가 달라질 수 있으므로 절대적인 실제 크기보다는 상대적인 크기 특징을 우선 활용한다.

## 10. 최종 판단

최종적으로 색상 및 크기 특징을 이용하여 과일을 다음 세 가지 상태로 분류한다.

| 상태 | 의미 |
|---|---|
| Unripe | 수확 전 |
| Harvest Ready | 수확 적기 |
| Overripe | 과숙 또는 주의 |

초기 POC에서는 YOLO 객체 탐지와 OpenCV 기반 색상·크기 분석 Rule을 적용하고, 향후 데이터가 충분히 확보되면 숙도 분류 모델로 고도화한다.

# AI 모델 선정 및 학습·검증 계획 보고서

## 1. 모델 선정

본 프로젝트의 목표는 카메라 영상에서 과일을 탐지하고, 탐지된 과일의 색상·크기 등의 특징을 분석하여 수확 적기를 판단하는 것이다.

따라서 단순한 이미지 분류 모델보다는 객체 탐지(Object Detection) 모델인 YOLO 계열 모델을 적용한다.

YOLO는 한 장의 이미지에서 과일의 위치와 크기를 Bounding Box 형태로 탐지할 수 있어 여러 개의 과일이 동시에 존재하는 농업 환경에 적합하다.

특히 본 프로젝트는 Raspberry Pi 5에서 실시간으로 동작하는 Edge AI 시스템을 목표로 하기 때문에 높은 정확도뿐만 아니라 추론 속도와 모델 크기도 중요하다.

따라서 초기 POC에서는 경량 YOLO 모델을 우선 적용하고, Raspberry Pi 5에서 실제 FPS와 추론 시간을 측정하여 최종 모델을 선정한다.

### 모델 선정 기준

| 기준 | 내용 |
|---|---|
| 탐지 성능 | 과일을 정확하게 탐지할 수 있는가 |
| 추론 속도 | Raspberry Pi 5에서 실시간 처리가 가능한가 |
| 모델 크기 | Edge 디바이스에서 실행 가능한 크기인가 |
| 다양한 환경 대응 | 그림자, 직사광선, 잎·가지 등의 환경에서 탐지가 가능한가 |
| 확장성 | 향후 다른 작물에도 적용할 수 있는가 |

## 2. 모델 학습 방법

본 프로젝트의 AI 처리 과정은 다음과 같이 구성한다.

**Camera Image → YOLO Fruit Detection → Bounding Box → Fruit Crop → Color/Size Analysis → Harvest Readiness Decision**

### 2-1. 데이터 수집

다양한 환경에서 과일 이미지를 수집한다.

- 미숙 과일
- 수확 적기 과일
- 과숙 과일
- 잎에 가려진 과일
- 여러 과일이 겹쳐 있는 경우
- 다양한 촬영 거리와 각도
- 직사광선
- 그림자
- 다양한 밝기
- 복잡한 배경

이를 통해 실제 농업 환경에서 발생할 수 있는 다양한 상황을 학습 데이터에 포함한다.

### 2-2. 데이터 라벨링

YOLO 학습을 위해 과일의 위치를 Bounding Box로 표시한다.

### 2-3. 데이터 분할

수집한 데이터는 Training, Validation, Test 데이터로 분할한다.

- **Training Set:** 모델 학습에 사용
- **Validation Set:** 학습 과정에서 성능 확인 및 모델 설정 조정
- **Test Set:** 학습에 사용하지 않은 데이터로 최종 성능 평가

예상 분할 비율은 Training 70%, Validation 15%, Test 15%로 설정한다.

단, 동일한 촬영 장면이나 유사 이미지가 서로 다른 데이터셋에 중복되지 않도록 구성한다.

### 2-4. 데이터 증강

실제 농업 환경의 다양한 촬영 조건을 고려하여 필요한 범위에서 데이터 증강을 적용한다.

- 밝기 변화
- 약간의 회전
- 크기 변화
- 좌우 반전
- 일부 Crop

다만 본 프로젝트에서는 색상이 수확 적기 판단의 핵심 특징이므로 색상을 지나치게 변화시키는 증강은 최소화한다.

## 3. 수확 적기 판단 방법

YOLO 모델을 이용하여 영상에서 과일의 위치를 탐지하고, 탐지된 과일 영역을 Crop하여 OpenCV 기반 색상 및 크기 특징을 분석한다.

- **YOLO:** "과일이 어디에 있는가?"
- **OpenCV/Rule:** "수확할 때가 되었는가?"

초기 POC에서는 HSV/Lab 색상 정보와 상대적인 크기 및 형태 정보를 이용하여 Unripe, Harvest Ready, Overripe의 3단계로 분류한다.

향후 데이터가 충분히 확보되면 숙도 분류 모델을 추가하여 Rule 기반 판단을 AI 기반 숙도 분류 모델로 고도화할 수 있다.

## 4. 모델 검증 방법

학습이 끝난 모델은 Test 데이터로 성능을 평가한다.

### 4-1. 과일 탐지 성능

YOLO의 대표적인 객체 탐지 평가 지표를 사용한다.

- Precision
- Recall
- mAP@50
- mAP@50-95

특히 실제 수확 보조 시스템에서는 Recall도 중요하다.

과일을 놓치는 경우 실제 수확 가능한 과일을 발견하지 못할 수 있기 때문이다.

### 4-2. 수확 적기 판단 성능

OpenCV의 색상·크기 분석 결과와 실제 사람이 판단한 숙도 라벨을 비교한다.

- 실제 상태 Unripe / AI 판단 Unripe
- 실제 상태 Harvest Ready / AI 판단 Harvest Ready
- 실제 상태 Overripe / AI 판단 Overripe

이를 기반으로 다음 지표를 확인한다.

- Accuracy
- Precision
- Recall
- F1-score
- Confusion Matrix

## 5. Edge AI 성능 검증

| 평가 항목 | 측정 내용 |
|---|---|
| mAP | 과일 객체 탐지 성능 |
| Recall | 과일을 놓치지 않고 탐지하는 비율 |
| Readiness Accuracy | 수확 적기 판단 정확도 |
| Inference Latency | 한 프레임 처리 시간 |
| FPS | 초당 처리 가능한 프레임 수 |
| Model Size | Edge 디바이스에서의 모델 크기 |
| CPU / Memory | Raspberry Pi 사용량 |

본 프로젝트의 목표 KPI는 다음과 같이 설정한다.

- 과일 탐지 mAP ≥ 90%
- 수확 적기 판단 Accuracy ≥ 85%
- 수확 대상 Recall ≥ 90%
- Edge 추론 시간 ≤ 100 ms/frame
- 실시간 처리 ≥ 10 FPS

> ※ 위 수치는 현재 측정 결과가 아닌 개발 목표값이며, 실제 구현 및 테스트 결과에 따라 수정할 수 있다.

## 6. 최종 검증 시나리오

마지막에는 실제 촬영 환경을 가정하여 테스트한다.

**Test 1. 정상적인 밝기**  
→ 과일 탐지 및 숙도 판단

**Test 2. 강한 직사광선**  
→ 색상 변화에 따른 판단 성능 확인

**Test 3. 그림자**  
→ 어두운 환경에서 탐지 및 판단 확인

**Test 4. 잎에 가려진 과일**  
→ 부분 가림 상황에서 Recall 확인

**Test 5. 여러 과일이 겹친 상황**  
→ 개별 과일 탐지 성능 확인

**Test 6. 다양한 촬영 거리**  
→ Bounding Box 및 상대적 크기 분석 확인

**Test 7. Raspberry Pi 5 실시간 카메라**  
→ FPS와 latency 측정

# AI 모델별 기능 및 활용 사례 비교 보고서

## 1. 보고서 개요

### 1.1 작성 목적

본 보고서는 Claude, YOLOE, DINO-X, SAM 3, SigLIP, OCR, MediaPipe의 주요 기능과 활용 사례를 조사하고, 각 기술의 특징을 비교하여 프로젝트에 적용할 수 있는 가능성을 검토하는 것을 목적으로 한다.

각 기술은 자연어 처리, 객체 탐지, 이미지 분할, 이미지와 텍스트 간 의미 비교, 문자 인식, 실시간 랜드마크 추출 등 서로 다른 기능을 제공한다. 따라서 단순히 모델을 비교하는 것뿐 아니라 해결하려는 문제와 프로젝트 목적에 따라 적절한 기술을 선택하는 것이 중요하다.

### 1.2 비교 대상

- Claude: 대규모 언어 모델(LLM)
- YOLOE: 개방형 어휘 기반 객체 탐지 및 분할 모델
- DINO-X: 개방형 객체 탐지 모델
- SAM 3: 객체 탐지·분할 및 추적 기술
- SigLIP: 이미지와 텍스트의 의미적 유사도 분석 모델
- OCR: 이미지 내 문자 인식 기술
- MediaPipe: 실시간 온디바이스 머신러닝 솔루션 및 프레임워크

※ 비교 대상은 모두 동일한 종류의 모델이 아니다. Claude는 언어 모델, OCR은 문자 인식 기술의 범주, MediaPipe는 다양한 머신러닝 기능을 제공하는 프레임워크 및 솔루션 모음이다.

## 2. 모델 및 기술별 기능 분석

### 2.1 Claude

**주요 기능**

Claude는 텍스트와 이미지 입력을 이해하고, 자연어 답변 생성, 문서 작성, 코드 작성 및 분석 등을 수행하는 대규모 언어 모델이다.

**주요 활용 사례**

- 보고서와 기술 문서 작성
- 프로그램 코드 작성 및 오류 원인 분석
- 프로젝트 요구사항 정리
- AI 모델의 활용 방식과 개발 절차 검토
- 데이터 분석 결과에 대한 설명 작성

**프로젝트 적용 가능성**

과일 수확 적기 판단 시스템에서는 개발 계획 수립, Python 코드 작성 보조, 전처리 과정 문서화, 오류 해결 등에 활용할 수 있다. 다만 Claude 자체가 카메라 영상에서 과일을 실시간 탐지하거나 Raspberry Pi의 LED를 직접 제어하는 핵심 비전 모델은 아니다.

### 2.2 YOLOE

**주요 기능**

YOLOE는 텍스트나 시각적 프롬프트 등을 활용하여 다양한 객체를 탐지할 수 있는 개방형 어휘 기반 비전 모델이다. 객체의 위치를 바운딩 박스로 표시하며, 지원하는 작업에서는 객체 영역을 분할할 수도 있다.

일반적인 고정 클래스 객체 탐지 방식과 달리, 프롬프트를 이용해 탐지하고자 하는 대상을 유연하게 지정할 수 있다는 특징이 있다.

**주요 활용 사례**

- 이미지에서 사과, 바나나 등 과일 탐지
- 텍스트 프롬프트를 활용한 특정 객체 탐색
- 객체의 위치를 표시하고 후속 분석을 위한 영역 추출
- 다양한 객체가 포함된 이미지의 탐지 및 분할

**프로젝트 적용 가능성**

과일 수확 적기 판단 시스템에서 과일의 위치를 탐지하고 해당 영역을 추출하는 데 활용할 수 있다. 추출된 과일 영역은 OpenCV를 이용한 색상 및 형태 분석에 사용할 수 있다.

다만 실시간 처리를 목표로 하는 경우에는 기존 YOLO 계열 모델과 YOLOE의 실행 환경 및 처리 부담을 비교한 뒤 선택해야 한다.

### 2.3 DINO-X

**주요 기능**

DINO-X는 다양한 객체를 탐지할 수 있는 개방형 객체 탐지 기술이다. 텍스트 또는 시각적 정보를 활용하여 탐지 대상을 지정할 수 있으며, 지원 기능에 따라 객체의 위치나 영역 정보를 얻을 수 있다.

**주요 활용 사례**

- 이미지에서 과일, 잎, 가지 등 여러 객체 탐지
- 텍스트로 지정한 대상의 위치 확인
- 복잡한 배경에 포함된 객체 탐색
- 이미지 데이터의 객체 라벨링 작업 보조

**프로젝트 적용 가능성**

과일과 주변 잎·가지가 함께 촬영된 이미지에서 탐지 대상을 구분하거나 데이터셋을 구축하는 과정에 활용할 수 있다. 여러 객체를 구분하는 기능은 실제 농업 환경의 이미지 분석에 도움이 될 수 있다.

다만 실제 적용 전에는 사용 가능한 실행 방식과 컴퓨팅 자원을 확인해야 한다. 외부 API 또는 별도 서버가 필요한 방식이라면 Raspberry Pi 기반 실시간 시스템에 바로 적용하기보다 데이터 분석 및 검증용으로 활용하는 방안도 고려할 수 있다.

### 2.4 SAM 3

**주요 기능**

SAM 3는 텍스트나 시각적 프롬프트를 활용하여 이미지와 영상에서 원하는 객체를 찾고, 객체의 픽셀 단위 영역을 분할하며, 지원되는 환경에서 객체를 추적할 수 있는 기술이다.

객체 탐지 모델이 주로 사각형 형태의 위치 정보를 제공한다면, 이미지 분할 모델은 객체의 실제 윤곽에 가까운 마스크 정보를 제공할 수 있다는 차이가 있다.

**주요 활용 사례**

- 과일의 외곽 영역을 픽셀 단위로 분리
- 배경과 과일 영역 구분
- 영상에서 특정 객체의 영역 추적
- 이미지 분석을 위한 정밀한 객체 마스크 생성

**프로젝트 적용 가능성**

과일의 바운딩 박스 안에 잎이나 가지가 함께 포함되면 색상 분석 결과가 달라질 수 있다. 이때 SAM 3를 이용해 과일의 실제 영역을 분리하면 배경의 영향을 줄이는 데 도움이 될 수 있다.

다만 분할 결과가 항상 정확한 것은 아니므로 실제 이미지에서 검증해야 한다. 또한 실행 부담을 고려하여 초기 실시간 시스템의 필수 구성 요소보다는 오프라인 데이터 분석이나 정밀 분할 실험에 활용하는 방안을 우선 검토할 수 있다.

### 2.5 SigLIP

**주요 기능**

SigLIP는 이미지와 텍스트를 각각 의미 정보를 담은 벡터로 표현하고, 두 표현 사이의 유사도를 비교할 수 있는 이미지-텍스트 모델이다.

이미지에 포함된 객체의 정확한 위치를 찾는 객체 탐지 모델과 달리, 이미지와 설명 문장 사이의 의미적 관계를 비교하는 데 중점을 둔다.

**주요 활용 사례**

- 이미지와 설명 문장의 유사도 비교
- 텍스트 설명을 이용한 이미지 검색
- 이미지 분류를 위한 제로샷 접근 방식 실험
- 이미지 데이터셋의 의미 기반 검색 및 정리

**프로젝트 적용 가능성**

과일 이미지와 ‘덜 익은 과일’, ‘수확 적기의 과일’, ‘과숙한 과일’과 같은 설명 문장 사이의 유사도를 비교하는 실험에 활용할 수 있다.

다만 유사도가 가장 높은 설명을 선택했다고 해서 실제 숙도가 정확하게 판정되는 것은 아니다. 조명, 품종, 촬영 환경 등에 따라 결과가 달라질 수 있으므로 실제 라벨이 있는 데이터셋을 이용해 검증해야 한다.

### 2.6 OCR

**주요 기능**

OCR(Optical Character Recognition)은 이미지나 영상에 포함된 문자를 인식하여 텍스트 데이터로 변환하는 기술이다. 인식 가능한 문자와 언어는 사용하는 OCR 엔진에 따라 달라진다.

**주요 활용 사례**

- 문서 및 인쇄물의 텍스트 추출
- 제품 라벨과 포장 정보 인식
- 촬영된 기록지의 문자 디지털화
- 화면이나 계측 장치에 표시된 문자 인식

**프로젝트 적용 가능성**

현재 과일 수확 적기 판단 시스템의 핵심 기능은 과일 탐지와 숙도 분석이므로 OCR을 반드시 사용할 필요는 없다.

향후 농산물 라벨, 재배 기록, 장비 화면 또는 작업 기록지를 자동으로 읽는 기능을 추가한다면 활용할 수 있다. 따라서 현재 프로젝트에서는 핵심 모델보다 확장 기능에 적합한 기술로 판단한다.

### 2.7 MediaPipe

**주요 기능**

MediaPipe는 손, 얼굴, 신체 등의 랜드마크 추출과 제스처 인식 등 다양한 머신러닝 기능을 제공하는 프레임워크 및 솔루션 모음이다. 지원되는 환경에서 카메라 입력을 이용한 실시간 분석과 온디바이스 처리를 구현할 수 있다.

**주요 활용 사례**

- 손의 위치와 관절 좌표 추출
- 손동작을 이용한 인터페이스 제어
- 얼굴 및 신체 랜드마크 분석
- 카메라 기반 동작 인식

**프로젝트 적용 가능성**

과일 수확 적기 판단 시스템에 작업자의 손동작을 이용한 제어 기능을 추가할 경우 활용할 수 있다. 예를 들어 손짓으로 다음 과일을 선택하거나 분석 화면을 전환하는 방식이다.

다만 MediaPipe는 과일 숙도를 판별하기 위한 핵심 기술이 아니므로, 현재 프로젝트에서는 사용자 인터페이스 확장 기술로 검토하는 것이 적절하다.

## 4. 과일 수확 적기 판단 시스템에 대한 적용 방안

본 프로젝트는 Raspberry Pi 기반 Edge AI 환경에서 과일을 탐지하고, 과일의 색상과 형태 정보를 분석하여 수확 적기를 판단하는 것을 목표로 한다. 따라서 모델을 선택할 때는 기능뿐 아니라 실행 환경, 실시간 처리 가능성, 구현 난이도도 함께 고려해야 한다.

### 4.1 핵심 처리 과정

1. 카메라를 통해 과일 이미지 또는 영상을 입력한다.
2. 객체 탐지 모델을 이용해 과일의 위치를 찾는다.
3. 탐지된 과일 영역을 추출한다.
4. OpenCV를 이용해 HSV 또는 Lab 색상 특징과 크기·형태 정보를 분석한다.
5. 분석 결과를 바탕으로 미숙, 수확 적기, 과숙의 세 단계로 분류한다.
6. 결과를 화면에 표시하고 필요에 따라 LED 등 하드웨어 출력과 연동한다.

### 4.2 기술별 우선순위

**우선 적용: 객체 탐지 모델 + OpenCV**

초기 POC에서는 Raspberry Pi에서 실행할 수 있는 YOLO 계열 객체 탐지 모델을 중심으로 구성하고, OpenCV 기반 색상 및 형태 분석을 결합하는 방식을 우선 검토한다. YOLOE는 개방형 어휘 탐지가 필요한 경우 비교 대상으로 사용할 수 있다.

**선택 적용: DINO-X 및 SAM 3**

DINO-X는 다양한 객체를 탐지하거나 데이터셋 구축을 보조하는 용도로 검토할 수 있다. SAM 3는 과일의 실제 영역을 정밀하게 분리해야 할 때 실험적으로 적용할 수 있다. 다만 두 기술 모두 실제 실행 환경과 처리 부담을 확인한 뒤 적용 여부를 결정한다.

**실험 적용: SigLIP**

이미지와 숙도 설명 문장 사이의 유사도를 비교하는 실험에 활용할 수 있다. 기존 OpenCV 기반 판단 결과와 비교하여 보조적인 숙도 분석 방식으로서의 가능성을 확인한다.

**확장 적용: MediaPipe 및 OCR**

MediaPipe는 작업자의 손동작을 이용한 시스템 제어 기능에, OCR은 재배 기록이나 라벨 인식 기능에 활용할 수 있다. 두 기술은 현재 핵심 기능 구현 이후 필요에 따라 추가한다.

**개발 보조: Claude**

Claude는 코드 작성, 오류 해결, 모델 비교, 기술 문서 작성 등 개발 과정의 보조 도구로 활용한다.

## 5. 모델 선정 시 고려 사항

각 기술은 서로 다른 문제를 해결하므로 하나의 기준으로 우열을 판단하기 어렵다. 실제 적용 전 다음 사항을 검토해야 한다.

- **기능 적합성:** 과일 탐지, 영역 분리, 숙도 분석 등 필요한 작업을 수행할 수 있는가?
- **실행 환경:** Raspberry Pi에서 직접 실행할 수 있는가, 아니면 별도 서버나 외부 API가 필요한가?
- **실시간성:** 카메라 입력부터 판단 결과 출력까지의 처리 과정이 프로젝트 요구사항에 부합하는가?
- **구현 난이도:** 데이터 준비, 모델 설정, 의존성 설치 및 하드웨어 연동이 가능한가?
- **검증 가능성:** 실제 과일 이미지와 정답 라벨을 이용해 결과를 확인할 수 있는가?
- **유지보수성:** 모델과 라이브러리를 프로젝트 환경에서 지속적으로 관리할 수 있는가?

특히 개방형 객체 탐지 모델이나 이미지 분할 모델이 제공하는 기능이 다양하더라도, 실제 하드웨어에서 요구되는 처리 속도와 자원 사용량을 확인하지 않고 실시간 적용이 가능하다고 단정해서는 안 된다.

## 6. 결론

본 보고서에서는 Claude, YOLOE, DINO-X, SAM 3, SigLIP, OCR, MediaPipe의 기능과 활용 사례를 비교하였다. 각 기술은 언어 처리, 객체 탐지, 이미지 분할, 이미지-텍스트 의미 비교, 문자 인식, 동작 분석 등 서로 다른 목적을 가진다.

과일 수확 적기 판단 시스템의 초기 구현에서는 과일 탐지와 색상·형태 분석을 연결하는 구성이 프로젝트 목표에 가장 직접적으로 부합한다. 따라서 객체 탐지 모델과 OpenCV를 중심으로 기본 시스템을 구현하고, 필요에 따라 이미지 분할이나 이미지-텍스트 유사도 분석을 추가로 검토하는 것이 적절하다.

최종 모델은 기능 설명만으로 확정하지 않고, 실제 데이터와 Raspberry Pi 실행 환경에서의 검증을 거쳐 선정해야 한다.
